# ADR-0008：v1 安全模型沿用 MicYou

- 状态：Accepted（2026-11-14 确认：v1 不做应用层鉴权）
- 日期：2026-11-14

## 背景

MicYou 的局域网链路没有认证与加密：

- TCP 连接只校验固定握手串（`MicYouCheck1` / `MicYouCheck2`），任何局域网设备都能伪装。
- UDP 音频包明文传输，可被同网段抓包或注入。
- 没有 PIN、配对或证书交换。

liino 若保持协议互通（ADR-0006），就无法单方面加 TLS 而不同时破坏兼容性。蓝牙 RFCOMM 则依赖操作系统的配对与链路加密。

## 决策（推荐）

1. v1 沿用 MicYou 的安全模型：**仅限可信局域网**，不提供应用层认证/加密。
2. 蓝牙链路的安全边界由 OS 配对提供；未配对设备不能建立 RFCOMM。
3. 明确禁止把 TCP/UDP 端口暴露到公网；文档与 UI 提示“仅在可信网络使用”。
4. 后续可选增强（不破坏 v1 互通）：
   - 连接前显示一次性 PIN，由用户在两端确认；
   - 在 protobuf 末尾追加可协商的加密能力字段，双方都支持时升级；
   - 设备指纹/信任列表。
5. 麦克风使用始终显示前台通知（Android）与菜单栏状态（桌面），不静默采集。

## 代价

- 同网段攻击者可以窃听/注入音频，或冒充设备。
- 不能宣称“端到端加密”。
- 后续加 PIN/TLS 需要协议扩展与 UI 流程。

## 备选方案

- 立刻上 TLS + 证书（类似 LocalSend）：安全性最好，但与 MicYou 不互通，且需要重做发现/配对；推迟到 Phase 5。
- 仅蓝牙、不做 LAN：可用性差，否决。

## 已确认

- v1 接受无鉴权局域网模型，仅在可信网络使用；PIN/TLS 作为后续增强。
